# Tinnis · 沿线小镇

一条地方铁路，三座慢慢生长的小镇。日式微缩景观三维铁路经营游戏，当前完成 **第 4 阶段：客流与乘客运输**。

## 启动

需要 Node.js 24+（本环境 24.19.0 / npm 11.9.0），支持 WebGL2 的浏览器。

```sh
cd /workspace/Tinnis
npm ci
npm run dev
```

开发服务器监听 `0.0.0.0:5173`。在其他电脑克隆时，进入对应仓库目录即可。`.nvmrc` 固定本阶段运行版本；`.npmrc` 将 npm 缓存放在仓库内的忽略目录，避免云环境主目录不可写。

## 当前可以做什么

- 观察汐港、青溪、枫泉与海岸、河流、山谷、稻田和温泉。所有模型程序化生成，资源无需联网获取。
- 旋转、平移、缩放、全景复位；点击 A/B/D 候选站位或聚落卡片，查看站位资料并定位。A/B 初期可建，D 第 7 阶段解锁，C 为可选预留。
- 在「车站」点击 A/B 候选站并确认建设，各花费 8000；B 包含两个会让泊位及站内轨道。已建车站可改名、定位、拆除。
- 在「铺轨」依次点击两个地图节点，或使用起终点下拉框。靠近节点的地面点击会吸附；轨道沿预设走廊预览，确认前不扣费。A—B 三段共 12000，可分段建设，已有轨道不重复计费；D/C 走廊保持锁定。
- 在「线路」编辑停站顺序（保存后生效）或反向停靠。有效路径只通过已建轨道计算，画面与后续运行共用节点数据；底部是固定 A—B—D 地理示意。两站一线初建合计 28000，余额应为 72000。
- 单段轨道与车站都可拆除，确认后返原购建价 50%，每个购建实例只退一次；车站拆除保留周围轨道。缺站或断轨立即使线路失效。经营结算在第 5 阶段接入。
- 在「列车」购买轻型（22000 / 24 人）或大容量车（38000 / 48 人），最多一列。投放后自动按单程 90 分钟、停站 10 分钟往返，支持跟车旅行；到站停运、回库后可按原价 60% 出售。已投放列车依赖的轨道/车站不能拆除；运行中的停站顺序修改在下一安全停站生效。
- 在「客流」查看候车、车上、完成、放弃与载客率。A↔B 潜在需求初设 360 人/游戏日，早晚通勤集中；只有运营中的直达服务才接受旅客，无服务需求与价格拒绝单独计数。先进先上，满载拆批，未上车者保留原排队时间，240 游戏分钟后放弃。站台用每站最多 6 个可见人物代表统计客流。
- 到站先下后上，只卸下当前目的地乘客；上车锁定票价，到达生成唯一完成事件。「待结算票款」为已记录的到达票款，实际财务结算留给第 5 阶段；本阶段不会凭渲染帧或重复到站增加余额。已有乘客的车在停运请求后先送达下一站，空车才能回库出售。
- 暂停、继续、1/2/4 倍时间；查看日期时间和初始资金 100000。
- 每 15 秒及成功建设/编辑后自动保存；通过右上角「存档」手动保存、读取、导入和导出 JSON。保存地图标识、相机、时钟、资金、聚落等级、选择状态，以及站名、轨道、停站顺序、原价购建凭据和退款记录。存档位于当前浏览器/站点的 localStorage，清理浏览器数据前请导出备份。当前 v4 兼容 v1/v2/v3：保留旧世界和资金，必要时初始化空铁路/空车库；旧本地存档键保留作备份，之后保存到 v4 键。车辆状态、方向、距离、剩余停站时间与购车记录一并保存。v3 迁移保留列车，新增空客流状态，从保存时刻继续生成需求，不回填历史旅客。v4 保存需求余数、排队时间、拆批身份、车上锁定票价、完成事件及统计。预览和未确认工程不写入存档。

## 验证

```sh
npm run check        # TypeScript
npm test             # 29 组模拟/建设/车辆/客流/存档规则测试
npm run build        # 类型检查 + dist 发行包
npm run test:e2e     # 先 build；自动启动独立预览服务，实际运行 Chromium
npm run test:train   # 实际浏览器单车三次往返与三种运行状态存档
npm run test:passengers # 实际候车/24人满载/完成/放弃/离线恢复
npm run verify       # 类型、规则、构建和全部 39 组浏览器检查
npm audit            # 依赖安全检查
```

浏览器脚本默认使用 `/usr/bin/chromium`；其他系统可设置 `CHROMIUM_PATH`。它执行桌面操作、真实节点附近吸附、双指输入、建拆与资金检查、站名/停站顺序编辑、v1 迁移、保存重载、JSON 导入导出和断网重载，基础 test:e2e 共 23 组检查（9 组场景回归 + 14 组建设验收）；test:train 另有 7 组单车验收，test:passengers 另有 9 组客流验收，总计 39 组，并自动清理测试浏览器/预览进程。截图、下载存档和性能报告输出到忽略目录 `artifacts/`。最新客流证据在 `stage-4-arrival.png`、`stage-4-mobile.png`、`passenger-report.json`；单车三次往返证据在 `stage-3-train-report.json`。建设证据包括 `stage-2-built.png`、`stage-2-berths.png`、`stage-2-preview.png`、`stage-2-mobile.png` 与 `construction-report.json`。附加 `?diagnostics=1` 可通过 `window.__ALONGLINE__.snapshot()` 获取只读状态/绘制诊断；正常界面不显示调试数据。

## 离线发行

```sh
npm run build
npm run preview       # 预览 dist，默认端口 4173
# 或使用本地已有的静态服务器，不需要 Node 依赖：
python3 -m http.server 8080 --directory dist
```

整个 `dist/` 即离线发行目录，可以复制或压缩分发。请通过静态 HTTP 服务打开，不使用 `file://`。Three.js、脚本、样式和图标均随包分发，无 CDN、远程字体或运行时 API。生产版首次成功访问后用 service worker 缓存完整发行资源，支持离线重载；service worker 需要 HTTPS 或 localhost。开发模式不注册缓存，避免影响热更新。
